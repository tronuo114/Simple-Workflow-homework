# 验收项

审查 Agent 与自动验收都按这份清单逐条核对，编号固定，不要改动。

- **REQ-1 LRU 淘汰**：容量满时淘汰最久未使用（最近最少使用）的条目。
  判定：依次 put a/b/c，get(a) 后再 put(d)，被淘汰的必须是 b。
- **REQ-2 TTL 过期与惰性删除**：条目超过 `ttl_seconds` 后，`get` 返回 None，
  且该条目要真的从容器里移除（`len` 减少），不能只是返回 None。
- **REQ-3 覆盖刷新 TTL**：`put` 已存在的 key 时，值和过期时间一起刷新，
  不能沿用旧的过期时间。
- **REQ-4 过期不占容量**：容量满时先清理过期条目，再考虑淘汰有效条目；
  全部条目过期后写入新条目不应产生任何有效条目淘汰。
- **REQ-5 线程安全**：并发 `get`/`put` 不抛异常、不死锁、容量不越界。
  必须有真正的锁（`threading.Lock` / `RLock`），且临界区用 `with` 管理。
- **REQ-6 均摊 O(1)**：`get`/`put` 内不得出现全表扫描或排序
  （`sorted` / `min` / `max` / 遍历全部 key）。容量大小不应影响单次操作耗时。

## 附加检查（不计入硬性否决）

- 构造参数非法（capacity<=0、ttl<=0）应抛 `ValueError`，类型不对抛 `TypeError`。
- 使用单调时钟（`time.monotonic`），避免系统时间回拨导致误过期。
