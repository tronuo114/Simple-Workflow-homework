# DEC-007 · TTLCache 数据结构：OrderedDict + 到期双端队列（放弃最小堆）

- **状态**：已采纳
- **日期**：2026-10-25
- **范围**：项目级（TTLCache 实现）
- **关联**：DEC-008、DEC-009、`solutions/ttl_cache.py`

## 背景

题目要同时满足三件互相拉扯的事：LRU 淘汰、TTL 过期、`get`/`put` 均摊 O(1)。
困难在于「怎么以 O(1) 找到已过期条目」——如果每次写都扫一遍全表，容量一上来就退化；
如果用最小堆，`push`/`pop` 是 O(log n)，严格口径下不满足 O(1)。

## 可选项

1. **dict + 每次扫描找过期**：实现最简单，但 `put` 是 O(n)，不可接受。
2. **OrderedDict + 按 `expire_at` 排序的列表**：查找要二分 + 删除要移动元素，O(n)。
3. **OrderedDict（LRU）+ 最小堆（到期时间）**：精确、通用，但每次操作 O(log n)，
   且堆不能直接删元素，要懒删除 + 版本号，实现复杂度不低。
4. **OrderedDict（LRU）+ 双端队列（到期时间）+ 版本号**：因为 TTL 固定、
   `time.monotonic()` 单调，入队顺序天然就是到期顺序，队首即最早到期，均摊 O(1)。

## 决定

选 **方案 4**：
- `_data: OrderedDict[key, _Entry]` 承担 LRU（`move_to_end` / `popitem(last=False)` 均 O(1)）；
- `_expiry: deque[(expire_at, key, version)]` 按到期时间非降序；
- 每个条目带 `version`，覆盖刷新或淘汰后旧队列记录自动失效（陈旧元组直接丢弃）；
- 队列长度超过 `2 * capacity + 32` 时压缩一次（O(n)），摊销到 n 次写入仍是均摊 O(1)。

## 理由

- 只依赖「TTL 是全局统一的」这一个前提，就把「找最早到期」从 O(log n) 降到 O(1)。
  代价是失去「每个 key 单独 TTL」的能力，而题目没有这个要求。
- 版本号解决了「队列里的死记录」：结构上不会出现悬空引用，也不需要反向索引。
- 压缩阈值与容量挂钩，保证队列长度有界（测试 `test_expiry_queue_stays_bounded` 断言这一点）。

## 代价与后果

- **不支持 per-key TTL**：若要支持，队列不再天然有序，必须回到最小堆方案（新开 DEC）。
- 惰性删除会留下少量陈旧元组，内存占用略高于「精确结构」，但上界为 `2*capacity+32`。
- 依赖单调时钟：用 `time.time()` 遇到系统时间回拨会误判过期/过晚，
  所以实现里用 `time.monotonic()`，并保留 `clock` 注入点给测试用。

## 复核条件

出现「不同条目不同 TTL」「需要精确的过期回调」需求时，改用最小堆 + 惰性删除的方案 3。
