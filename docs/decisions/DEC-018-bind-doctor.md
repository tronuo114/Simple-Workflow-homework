# DEC-018 · 面板禁用离线模式；新增 /bind、/unbind、/test

- **状态**：已采纳
- **日期**：2026-10-25
- **范围**：项目级
- **关联**：DEC-005、DEC-015、DEC-016

## 背景

面板此前默认 mock，用户以为「能跑」但实际跑的是脚本化输出；同时 `/key` 只能绑定、不能解绑，
出问题（401 / 改错 Key）时没有自检手段，只能靠猜。

要求：
1. **离线模式在面板中禁用**，避免演示与真实两套预期混在一起；
2. 绑定/解绑要有对称指令；
3. 提供一条 `/test`，能一眼判断「现在能不能真的跑起来」。

## 决定

### 1. 面板固定 live

- 去掉 mock/live 单选，`build_command` 恒带 `--live`；
- `/mode` 保留为提示指令：告知已禁用并给出命令行替代；
- 没有 Key 时启动提示、运行失败提示都直接导向 `/bind`；
- 离线 mock **只保留在 CLI**（`run --task … --mock`），用于离线验收与测试。

### 2. 指令集

| 指令 | 语义 |
| --- | --- |
| `/bind <key>` | 写入 `.env` 的 `AGENT_API_KEY`，回显脱敏（前后 4 位） |
| `/bind` | 查看绑定状态 |
| `/unbind` | 从 `.env` 删除 `AGENT_API_KEY` |
| `/key` | 兼容别名（等同 `/bind`） |
| `/test` | 调 `workflow.cli doctor --events`，逐项渲染检查结果 |

### 3. `/test` 的检查项（`workflow/doctor.py`）

| 检查 | 失败时的含义 |
| --- | --- |
| 项目文件 | exe 被单独拷走 / `WORKFLOW_HOME` 指错 |
| 运行目录可写 | 盘只读、权限不足，`runs/` 写不进去 |
| 模型配置 | provider / model / base_url 解析不出来 |
| API Key | 未绑定，提示 `/bind` |
| 模型连通 | 真实发一次 `max_tokens=1` 的请求，报告状态码与耗时；401 单独给「Key 失效」提示 |
| 验收器 pytest | 打包缺 pytest，需重跑 `build_exe.ps1` |
| 事件流序列化 | 面板渲染依赖的 JSONL 是否正常 |

## 理由

- **演示可信度**：面板展示的是真实调用链，离线脚本只用于 CLI 自测，避免「看起来通过」的误判；
- **对称指令**：能绑就能解，换 Key、换账号、排查鉴权都简单；
- **把排错前置**：`/test` 把「文件 / 权限 / 配置 / Key / 网络 / pytest」分成 7 个独立结论，
  失败时给下一步动作，而不是只抛一句 `LLMError`。

## 代价与后果

- 没有 Key 就无法用面板演示；README 与启动提示都写明先 `/bind`，并保留 CLI mock 兜底。
- `/test` 会真实发起一次最小模型请求（约 1 token），有极小的计费与网络依赖；
  离线场景可用 `python -m workflow.cli doctor --offline` 跳过网络检查。
- 指令集扩大后，`/help` 需要与实现同步维护（已有测试断言帮助文本包含关键指令）。

## 复核条件

若以后要恢复面板离线演示，应做成显式的「演示模式」并打水印（如标题栏标记 DEMO），
避免用户把脚本化输出当成真实模型结果；同时保留 `/test` 作为入口。
